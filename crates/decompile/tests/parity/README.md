# prepare-ladder parity fixtures

Byte-parity corpus for the Rust port of the deterministic preparation ladder
(`src/prepare/`) against the Python reference implementation
(`evaluation/scripts/prepare_candidate.py`).

## Cases

- `erc20-raw/` — raw decompiler output of the `modern-oz-erc20` fixture
  (arm-neutral decompilation recorded during the sealed holdout runs).
- `blockreader-raw/` — same for the `modern-block-reader` fixture.
- `lighthouse-raw/` — same for the `lighthouse` fixture (tier-2 batch 2); the
  corpus where the scope-honest `selfref`/`vars`/`truthiness` semantics and
  stages 15-18 fire.
- `hdwallet-raw/` — same for the `hdwallet` fixture; fires `vars`,
  `truthiness`, and `typed-packed-literals`.

Each case directory holds `input.sol` and the Python ladder's cumulative
output after every stage, `stageNN-<name>.sol` in
`PREPARE_STAGES`/registry order.

## Provenance

References generated by the Python implementation
(`evaluation/scripts/prepare_candidate.py`):

```python
stages = prepare_candidate.prepare_stages(source)   # full 18-stage ladder
# stage k cumulative output == stages[k - 1].source
```

Stages 1-13 of `erc20-raw`/`blockreader-raw` were generated at the port's
base commit; stages 14-18 of those cases and the whole `lighthouse-raw` /
`hdwallet-raw` corpora were generated at the 18-stage ladder freeze that
sealed tier-2 batch 2 and the read-guard repair. The full-ladder finals
reproduce the sealed seeds byte-exactly:

- `erc20-raw` stage18 == `evaluation/results/fresh-holdout-v6/seeds/erc20-v5.sol`
  (sha256 `b7d4b2369ca74cd0…`)
- `blockreader-raw` stage18 == `evaluation/results/fresh-holdout-v4/seeds/blockreader-v4.sol`
  (sha256 `91f95c91a8835410…`)
- `lighthouse-raw` stage18 == `evaluation/results/lighthouse-tier2-v1/seed/prepared.sol`
  (sha256 `444d408373d84539…`)
- `hdwallet-raw` stage18 == `evaluation/results/hdwallet-tier2-v1/seed/prepared.sol`
  (sha256 `9b90533b0eb54c37…`, re-derived under the pass2-rendering re-freeze of
  2026-11-12; the pre-freeze seed `761bb828…` stands as history in git)

The Rust parity test asserts every registry prefix against the matching
`stageNN-*.sol` reference, so each porting slice extends the checked prefix
until the full ladder is covered.
